# Interaction flow evaluation cases

These compact cases test review judgment with raw source excerpts or shared-walker observations. They are source-only behavioural evaluations, not browser/usability studies. They require no credentials, live service, dependency installation or product writes.

## Run

Use a fresh evaluator session with the current interaction-flow skill and one case directory (or a small batch of separate cases) from `evals/interaction-flow/`. Give it only that case's request.md and artifacts.md, not this rubric, another evaluator's answer or the expected outcome. Write its response outside the repository. Independent cases may run in parallel when authorized.

Judge decisions and evidence, not exact wording or headings. Keep the skill revision, case, observed outcome and limitations with any test report. A successful manual case does not establish real-browser correctness or reliability on every product.

## Rubric

| Case | What a useful response demonstrates | Material failures |
|---|---|---|
| local-worktree | Complete goals (find/resume, new map, authoring/detail), concrete search/creation concerns with source limits, Table assessed as a promised future shared-model path | Critiques excluded inspector; demands metrics; removes legitimate graph/table or navigation entry points; claims browser reproduction |
| site-only | Useful booking/return and recovery review using supplied observations, preserves review/confirmation benefits, source/version/write completion unknown | Requires repository/roadmap or refuses to proceed; invents implementation, timings or completed booking; treats disabled Group bookings as shipped failure |
| superseded-flow | Separates explicit old implementation, accepted automatic target and planned delivery; next action links R6/R1 and tests save-triggered parent propagation/failure | Proposes renaming/repositioning Recalculate as the target daily flow; reopens settled automatic/manual choice; claims planned means implemented |
| proposal-tradeoff | Keeps recipient/scope verification and retained drafts, identifies ambiguous contacts, compares credible safe alternatives, routes payload uncertainty to investigation | Equates fewer clicks with better UX; accepts unverified sensitive payload; removes useful duplicate entry; claims send success or measured improvement |

Across cases assess useful prioritization, consequence-based findings, confidence and unknown estimates, concrete validation, preservation of current benefits, and avoidance of new permission/setup ceremony. Record partial passes honestly; revise the skill only for demonstrated failures, not wording preferences.

## Browser follow-up

The fixtures intentionally cannot validate screenshots, actual focus, status announcements or persistence. Run relevant manual-tests.md tasks against an authorized local disposable build or read-only deployed site for those claims. A real representative journey remains the acceptance test for an implemented UX fix.

## Recorded run on 23 October 2026

Two independent fresh evaluator sessions each reviewed a batch of two separate cases using only request.md, artifacts.md and the candidate skill. The rubric was withheld. All four responses were inspected against the material-failure criteria:

- **local-worktree: pass.** Covered find/return, creation, sparse authoring and the future Table; retained valid complementary views and excluded the inspector. Source concerns were not presented as browser reproduction.
- **site-only: pass.** Produced booking and return/recovery fixes without requesting source access, inventing timings or claiming a completed booking; preserved review/confirmation benefits.
- **superseded-flow: pass.** Linked the accepted automatic save-triggered target to existing planned work; did not reopen the decision or mistake local preview for cross-report propagation.
- **proposal-tradeoff: pass.** Preserved explicit send/preview and retained drafts, identified ambiguous recipients, rejected an unverified immediate-send shortcut and separated payload investigation from implementation.

This records source-only judgment checks, not browser execution, user research, measured improvement or a reliability benchmark. The cases are synthetic, the conclusions are manually judged, and broader independent products remain useful follow-up coverage.
